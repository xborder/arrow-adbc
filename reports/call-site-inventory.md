# Go ADBC Flight SQL `GetFlightInfo` call-site inventory

Inventory basis: upstream `4d50e2e30f9e96905a64644defe964447d54cbe7`, before the POC. Arrow Go's typed helpers named `Execute`, `GetSqlInfo`, `GetCatalogs`, and so on internally call `GetFlightInfo`; therefore the inventory follows those semantic calls, not only the literal string in arrow-adbc.

| File / method | Command family | Public applicability | POC routing |
| --- | --- | --- | --- |
| `flightsql_statement.go` `statement.ExecuteQuery` -> `sqlOrSubstrait.execute` -> `connectionImpl.execute` | statement SQL | Normal direct SQL `ExecuteQuery`, autocommit and transaction | Drain `ExecutePoll` synchronously to final cumulative info. Initial-only `UNIMPLEMENTED` falls back to the same `Execute` path. |
| `flightsql_statement.go` `statement.ExecuteQuery` -> `sqlOrSubstrait.execute` -> `connectionImpl.executeSubstrait` | statement Substrait | Normal Substrait `ExecuteQuery`, autocommit and transaction | Drain `ExecuteSubstraitPoll`; initial-only fallback to `ExecuteSubstrait`. Separate cache key from SQL. |
| `flightsql_statement.go` `statement.ExecuteQuery` -> `PreparedStatement.Execute` | prepared statement | Normal prepared query with or without record/stream parameters | Drain `PreparedStatement.ExecutePoll`. Its initial call performs binding once. If that poll alone is `UNIMPLEMENTED`, temporarily clear the already-applied local binding while `Execute` issues `GetFlightInfo`, then restore it for statement reuse. |
| `flightsql_database.go` `databaseImpl.Open` -> `Client.GetSqlInfo` | metadata SQL info | Internal transaction-support discovery performed for every physical connection | Route through the generic metadata polling adapter before capability detection. It shares the physical connection's SQL-info family cache. Shared-server test `DatabaseOpenTransactionProbe` proves three polls and no get. |
| `flightsql_connection.go` `connectionImpl.PrepareDriverInfo` -> `Client.GetSqlInfo` | metadata SQL info | Public `Connection.GetInfo` server values | Generic PollFlightInfo adapter using `CommandGetSqlInfo`; initial-only fallback preserves the existing behavior that tolerates a server with no SQL-info implementation. |
| `flightsql_connection.go` `connectionImpl.GetObjectsCatalogs` -> `Client.GetCatalogs` | metadata catalogs | Catalog stage of public `GetObjects` | Generic adapter using `CommandGetCatalogs`; shared-server T4 covers multi-step completion. |
| `flightsql_connection.go` `connectionImpl.GetObjectsDbSchemas` -> `Client.GetDBSchemas` | metadata DB schemas | Schema stage of public `GetObjects` for depths below catalog-only | Generic adapter using `CommandGetDbSchemas`. |
| `flightsql_connection.go` `connectionImpl.GetObjectsTables` -> `Client.GetTables` | metadata tables | Table/column stage of public `GetObjects` | Generic adapter using `CommandGetTables`. |
| `flightsql_connection.go` `connectionImpl.GetTableSchema` -> `Client.GetTables` | metadata tables | Public `GetTableSchema` | Same tables family/cache and generic adapter; final info enters the existing single-row schema extraction path. |
| `flightsql_connection.go` `connectionImpl.GetTableTypes` -> `Client.GetTableTypes` | metadata table types | Public `GetTableTypes` | Generic adapter using `CommandGetTableTypes`; final info enters the existing reader path. |
| `flightsql_statement.go` `statement.ExecutePartitions`, incremental disabled -> `PreparedStatement.Execute` or `sqlOrSubstrait.execute` | partition production | Public non-incremental partition enumeration | Deliberately unchanged. It produces serialized partitions rather than the normal query reader and is behaviorally separate from this POC. |
| `flightsql_statement.go` `statement.ExecutePartitions`, incremental enabled -> `statement.poll` | incremental partitions | Public incremental partition discovery | Deliberately unchanged: returns only newly discovered endpoints on each API call, retains progress/continuation state across calls, and can retry a later call after `UNAVAILABLE`. The existing `TestIncrementalPoll` suite passes unchanged. |

No additional PK/FK/cross-reference calls are hidden inside Go ADBC `GetObjects`. Its implementation builds the ADBC hierarchy exclusively from catalogs, DB schemas, and tables. Arrow Go exposes typed `GetPrimaryKeys`, `GetImportedKeys`, `GetExportedKeys`, `GetCrossReference`, and `GetXdbcTypeInfo` helpers, but this Go ADBC driver does not call them and exposes no separate public connection methods for them.

Excluded because they do not obtain `FlightInfo`: `ExecuteSchema` uses `GetSchema`; update and ingest paths use `DoPut`/`DoAction`; session, transaction, and prepared-statement lifecycle operations use their existing action/RPC paths.
